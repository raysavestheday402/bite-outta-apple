# CLAUDE.md

Notes for working on **Apple TV Library**, a kid-friendly launcher for the family's purchased Apple TV / iTunes kids movies and shows. It's saved to a young child's iPad home screen as **TV Library**, and tapping a poster opens that title in the Apple TV app.

- **Live site:** https://raysavesthedaylibrary.netlify.app
- **Deploys:** Netlify redeploys automatically on every push to `main`. There is no build step, so the repo root is served as-is.
- **Owner workflow:** Ray works on Windows and commits and pushes with GitHub Desktop. Write instructions for him with Windows paths and plain steps.

## Hard rules

- **Never put the child's name anywhere on the site**: not in pages, titles, alt text, the manifest, comments or commit messages that end up in served files. The header says "Movie Library". `python tools/check_data.py` checks for this.
- **Ratings don't matter** (Ray, Oct 2026): the library is whatever the family owns, including shows like Family Guy and The Goonies. Ratings aren't shown or checked.
- **She can't read yet.** There is no search or filter (Oct 2026). Controls must work from pictures alone (icons, posters, big tap targets). Don't add anything that only makes sense as text.
- **Keep it kid-proof.** No long-press popups or callouts, no text selection, no double-tap zoom (`touch-action: manipulation`). Don't add links that leave the app except the Apple TV links themselves.
- **Never commit API keys.** `keys.txt` is git-ignored. Don't print key values or put them in files that get committed.
- **Don't change the look casually.** The deep-space night scene with neon pink/blue/violet glow, neon-rimmed posters and the header (the neon "MOVIES" banner art; whole look redesigned at Ray's request Oct 2026) are deliberate. Ask before restyling.
- **No frameworks and no build step.** Plain HTML, CSS and JavaScript, so a push is a deploy.

## Layout

| Path | What it is |
|---|---|
| `index.html` | The whole app: markup, CSS and JS in one file. |
| `sw.js` | Service worker for offline use: the page and `data.js` load fresh when online (saved copy as fallback); posters, thumbs, icons and fonts load from the saved copy and refresh in the background. Bump `VERSION` when covers change under the same filename (it is `v3`). |
| `data.js` | `window.LIBRARY`, one entry per title. **Generated by `tools/build_data.py`; don't edit by hand.** |
| `posters/` | 600px-wide JPEG covers, named by id (`001.jpg`, `015a.jpg`). Generated. |
| `thumbs/` | 420px copies of the posters for the grid. Generated by `build_data.py`. |
| `icons/` | Home-screen icon (the neon superhero "MOVIES" icon), favicons, `header-art.jpg` (the banner), `manifest.webmanifest` (`short_name` is "Movies"). |
| `ping.txt` | One-word file the offline check fetches. The service worker never saves it, so a failed fetch means no internet. |
| `tools/cover_rows.json` | **The title list.** The single source every script reads (through `tools/libtools.py`). |
| `tools/apple_links.json` | Direct Apple TV ids found by `find_apple_links.py` or pasted with `--set`. Committed; wins over the Covers folder's Wikidata `apple-links.json`. |
| `tools/Redo Covers.bat` | Re-downloads covers for chosen ids (`update_library.py --redo 010a 010b`), e.g. wrong Halloweentown covers. |
| `tools/update_library.py` / `Update Library.bat` | Runs find_apple_links → get_covers --missing → build_data → check_data. Ray's one-click update. |
| `tools/find_apple_links.py` | Searches Apple TV (UTS search API, then the tv.apple.com search page, then the iTunes Store) for titles that only have a search link. Asks Ray when unsure. |
| `tools/libtools.py` | Shared helpers: flattens rows into titles (`items()`), the remembered Covers folder (`tools/covers_folder.txt`, git-ignored), matching. |
| `tools/get_covers.py` | Downloads posters (TMDB, then fanart.tv, then Wikipedia, then Apple TV art) plus details (year, rating) and Apple TV ids (Wikidata) into the Covers folder. `--missing` only fetches titles without a cover. |
| `tools/build_data.py` | Turns `tools/Covers/` into `data.js` and `posters/`. Holds the display-name, Disney & Pixar and Holidays lists. |
| `tools/check_data.py` | Offline sanity checks to run before pushing. |

Git-ignored and never committed: `keys.txt`, `Covers/` (any level), `site_check/`. Ray keeps the original hi-res covers, `details.json` and `apple-links.json` outside the repo in `C:\Users\raysa\Claude Files\Apple TV Archive\Covers`.

## The app (`index.html`)

- One IIFE reads `window.LIBRARY` and renders either the poster **Grid** or iPod-style **Cover Flow** (swipe, scrubber, "Play in Apple TV" button).
- No search, filters, favorites, Recent or "Show" badges (all removed Oct 2026 at Ray's request). Every title is one A to Z list, movies and shows mixed, numeric-aware so "Halloweentown 1–4" stay together.
- The header is sticky, hides when scrolling down and returns on any scroll up. It is one slim bar: the app icon and a neon "MOVIES" wordmark on the left over the banner art (a faded full-width backdrop), and three big buttons on the right: 🎲 Surprise (jumps to Cover Flow on a random title), Grid and Cover Flow. A 🚀 button returns to the top after a long scroll. Grid poster size scales with the screen width (`--col`).
- The header is about 62–84px tall. No years in Cover Flow, and no decorative star dots on the background (Ray wanted it clean and consistent). The footer is one small line with the required TMDB credit. Posters have a neon rim in one of five colours (picked from the id). Big type and tap targets throughout: she's five.
- **Crash fix:** the grid uses 420px `thumbs/` copies and an IntersectionObserver that sets `src` only near the screen and removes it far away (hundreds of decoded posters crashed iOS Safari). Cover Flow uses full posters with a small 17-cover pool. Don't add per-poster `translateZ`, `container-type` or backdrop blur.
- **Offline:** when the browser says it's offline, or `ping.txt` can't be fetched (checked on load, on online/offline events, when the app comes back to the front, every 30 s, and every 5 s while offline), a full-screen "No Wi‑Fi" cover hides and disables (`inert`) everything else. It has a big green **Open Downloads** button (`videos://`, iPhone/iPad only) and a big **Try again** button that re-checks and dismisses itself when the internet is back.
- The Cover Flow stage has `touch-action: none`, so swipes on the covers never scroll the page.
- **Broken links:** the only grown-up feature left. A small 🔗 button on each poster (and "Mark broken" in Cover Flow) flags a title red; a footer note then shows how many are marked, with Copy list (paste it to Claude) and Clear. Set `BROKEN_LINK_BUTTON = false` at the top of the script to strip all of it, and delete the `.brk` / `.link-flag` / `.mark` / `.broken-note` CSS if you want the code gone too. There is no link-check mode or `?test=1` any more.
- Per-device state in `localStorage` under `rstd:view` and `rstd:marks` (old `rstd:favs`, `rstd:chip`, `rstd:recent`, `rstd:test` are cleared on load), always through the `lsGet` / `lsSet` try/catch wrappers.
- Every list, All included, is one A to Z list with movies and shows mixed. Sorting ignores a leading "The/A/An".
- Escape any library text with `esc()` and links with `safeUrl()` when building HTML.

## A `data.js` entry

```js
{ "id": "101", "title": "PAW Patrol: The Dino Movie", "kind": "movie", "year": "2026", "rating": "PG",   // kept in the data but not shown
  "poster": "posters/101.jpg", "link": "https://tv.apple.com/us/movie/<slug>/umc.cmc.…", "direct": true, "tags": [] }
```

`direct: false` means no Apple TV id was found and `link` is an Apple TV search for the title instead.

## `cover_rows.json` fields

| Field | Meaning |
|---|---|
| `n` | Row number. It becomes the id and the file prefix (`001`). Append new titles with the next free number; never renumber, because link-check marks are saved by id. |
| `kind` | `"movie"` or `"tv"`. |
| `label` | Internal name. It's the key for `DISPLAY`, `DISNEY`, `HOLIDAY` and `NO_YEAR` in `build_data.py`, and the shown title unless `DISPLAY` overrides it. |
| `term` | What to search TMDB for. |
| `year` | Release year to pick the right match, or `""`. |
| `mode` | `""` normally, `"skip"` to leave the row out, `"multi"` for rows with special handling. |
| `wiki` | Exact Wikipedia page titles, used as a fallback poster source and for Wikidata ids. |
| `alts` | Other names to try on TMDB. |
| `choices` | Splits one row into several titles (`015a`, `015b`…), each with its own `kind`, `term`, `year` and optional `title`, `alts`, `apple`, `tags`. Used for collections (Halloweentown, `010a`–`010d`) so each movie gets its own link. Until a choice has its own cover, it borrows the row's old cover (`010 - ….jpg`). To remove a choice, give it `"skip": true` rather than deleting it, so later letters don't shift (Freakazoid `015b`). |
| `title` | Optional name to show (otherwise `DISPLAY` or `label`). |
| `apple` | Optional search term for Apple TV if it differs from `term`. |
| `tags` | Optional extra tags: `"plus"` for Apple TV+, `"holiday"`, `"disney"`. |

Animaniacs is row 5 (the one Ray owns, shown as 2023). The 1993 duplicate (`015a`) is skipped.

Rows 151 and up are the Apple TV+ kids & family titles.

## Updating the library

1. Add or edit rows in `tools/cover_rows.json`. Mark Disney/Pixar or holiday titles with `tags` (or add the `label` to `DISNEY` / `HOLIDAY` in `tools/build_data.py`), and give a `title` if the label isn't the name to show.
2. `pip install -r tools/requirements.txt` (once).
3. `python tools/update_library.py ["path\to\Covers"]` (or double-click `tools/Update Library.bat`). Ray's Covers folder is `C:\Users\raysa\Claude Files\Apple TV Archive\Covers`; the path is remembered after the first run. It looks up Apple TV links only for titles not yet on the site or still on a search link (never ones already direct), downloads covers only for titles with none in Covers or `posters/` (so the hand-added covers are kept), rebuilds `data.js` and `posters/`, and runs the checks. `build_data.py` falls back to the current `posters/`, `data.js` years/ratings and direct links, so an empty Covers folder loses nothing, and a title with no cover anywhere is left off the site. An `apple_links.json` entry may carry a full `url` (episode links, e.g. Halloweentown High `010c`).
4. Check new covers by eye, then commit and push. Netlify deploys in about a minute.

For a title that still opens a search: `python tools/find_apple_links.py --set <id> "<tv.apple.com link>"` (Ray gets the link from the Apple TV app's Share → Copy Link). A full re-download of every cover is `python tools/get_covers.py` with no flags.

The scripts need network access to TMDB, fanart.tv, Wikipedia, Wikidata and Apple (uts-api.itunes.apple.com, tv.apple.com, itunes.apple.com), which a cloud session may not have. Without it, edit only what doesn't need downloads and let Ray run step 3 locally.

## Testing changes

There is no test suite. For app changes, serve the folder (`python -m http.server`) and check it in a browser at iPad sizes (portrait and landscape) and phone width, in both Grid and Cover Flow, with the Grid / Cover Flow toggle and a long scroll. For offline, use the browser's offline mode after one load and reload. The real check is Safari on the iPad from the home-screen icon. For data changes, run `tools/check_data.py`.

## Play vs Buy on the iPad

A poster shows **Play** only if the iPad's Apple Account owns the title (Family Sharing with Purchase Sharing on counts), the purchase isn't hidden, and Screen Time allows the rating. That's account setup, not something the site can fix.
